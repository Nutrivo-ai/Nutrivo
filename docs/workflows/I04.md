Status: built (T-406). The `verify` Edge Function (supabase/functions/verify) answers `GET /verify/{ref}` by calling `public.verify_reference` with the anon key and passing on only status, issue date, ruleset version and whether Not assessed items existed; malformed and missing references get the identical `{"status":"unknown"}`. The public page `/verify/[ref]` (S-NV2-027, form at `/verify`) asks the function server-side and shows current, superseded or unknown, with loading and error states. Rate limits are best-effort per instance (per visitor on the web, per client and per instance in the function); a shared limiter is T-1103's. `I04.main`, `I04.must.1`, `I04.must.2` and `I04.fail.1` are tested in worker/tests/test_verify_pg.py, supabase/functions/verify/verify.test.mjs (via worker/tests/test_verify_function.py), apps/web/src/lib/public/verify.test.ts and apps/web/tests/e2e/verify.spec.ts. Open on #48: how much of the frame S-NV2-027 compares against, a durable rate limiter, and a document type for certificates (I03)
