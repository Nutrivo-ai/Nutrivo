# A01 · Sign up and create a workspace

| Domain | Register status | Scope | Milestone |
|---|---|---|---|
| Access | DRAWN | BUILD | M1 |

**Actor · trigger:** New user · signs up and confirms the email  
**Design:** Workspace Settings (People, Your account); Onboarding Flow; Account Recovery

## Steps
1. Supabase Auth creates the user (email and password or magic link, confirmation on).
2. The first authenticated request calls app.create_workspace(name).
3. One transaction creates the person, the workspace (plan free, regions EU), the admin membership and the allowance (3 labels).
4. Audit workspace.created; welcome email through O01.

## Database (Workflow Register)
auth.users insert; workspaces insert (region, plan=free, labels_allowed=3); memberships insert (role=admin, external=false); audit_events insert (workspace.created)

**Depends on:** Supabase Auth, email delivery, O01 notifications

## Must hold
- A workspace never exists without exactly one admin membership.
- The allowance starts at 3 allowed, 0 used.
- If any step fails, nothing persists.

## Failure and edge cases
- Email already registered: sign-in path, never a second user.
- Unconfirmed email: cannot create a workspace.

## Acceptance IDs (each needs a test carrying the ID in its title; docs/19)
- `A01.main` Sign up and create a workspace: the main path works end to end
- `A01.must.1` A workspace never exists without exactly one admin membership.
- `A01.must.2` The allowance starts at 3 allowed, 0 used.
- `A01.must.3` If any step fails, nothing persists.
- `A01.fail.1` Email already registered: sign-in path, never a second user.
- `A01.fail.2` Unconfirmed email: cannot create a workspace.

**Related backend rows:** BE-02, BE-03, pgTAP: create_workspace, e2e: sign up to workspace

Status: built in T-106, except step 4's welcome email.
