# C02 · Create a product from an artwork

| Domain | Register status | Scope | Milestone |
|---|---|---|---|
| Products | PART | BUILD | M3 |

**Actor · trigger:** Editor · drops a label file on the board  
**Design:** Nutrivo 2.0 (board, product)

## Steps
1. Signed upload to artwork/<workspace>/<product>/<sha256>.pdf.
2. Product created with a provisional name.
3. app.register_artwork, then extraction.

## Database (Workflow Register)
products insert; artwork_versions insert; extraction_runs insert

**Depends on:** D01

## Must hold
- As D01 and B02.

## Failure and edge cases
- An unsupported file type is rejected before upload.

## Acceptance IDs (each needs a test carrying the ID in its title; docs/19)
- `C02.main` Create a product from an artwork: the main path works end to end
- `C02.must.1` As D01 and B02.
- `C02.fail.1` An unsupported file type is rejected before upload.

**Related backend rows:** —

Status: built (T-303, T-401). The label-file card on Add a product checks the file in the browser (`C02.fail.1`), then `app.create_product_from_artwork` makes the product with a provisional name from the file, refusing first what the artwork would be refused for (P0036, P0032, counting products still waiting for their file), then the T-303 upload, `app.register_artwork` and extraction. It sits on Add a product until the board exists (T-506, #43 Q3).
