# 07 · AI

Models extract, classify and judge claims. They never decide coverage, never author rules and never produce a
verdict without a rule_key.

## One way to call a model
`nutrivo_worker.models.call(purpose, prompt_version, inputs, output_schema)` (T-008). No other code calls a model.
- **Purposes and model classes:**

  | Purpose | Model class |
  |---|---|
  | `classification`, `claim_judgement`, `extraction_secondary` | judgement |
  | `extraction_primary` | extraction |
  | `triage` | triage |
  | `smoke` | triage (the runtime's own test) |

  Ids come from `BEDROCK_MODEL_<CLASS>` and must be EU (`eu.`) profiles or in-Region ids: `global.` and `us.` profiles
  are refused at start-up. Dev uses `eu.anthropic.claude-sonnet-4-6` for judgement and extraction and
  `eu.anthropic.claude-haiku-4-5-20251001-v1:0` for triage until the 5.5 models are enabled on the AWS account
  (requested, not yet granted on 23 Oct 2026). The switch is configuration only, tracked in T-014: set the three
  `BEDROCK_MODEL_<CLASS>` values in Infisical, run `make doctor`, and rerun the claim evaluations.
- **Prompts:** `worker/prompts/<purpose>.<version>.md`. Each file has a header of `key: value` lines (purpose, model
  class, output schema, owner), then a line `---`, then the system prompt. Prompts are never edited in place once
  used: copy to the next version.
- **Output:** structured outputs (`output_config.format` with the pydantic schema, closed), then pydantic validation.
  A refusal raises `ModelRefused`; a truncated or invalid output raises `ModelOutputInvalid`. Both are withheld,
  never passed.
- **No sampling parameters.** The Messages API no longer accepts `temperature`, `top_p` or `top_k` (API version
  2026-10-21, and the anthropic Python SDK 1.x). Repeatable results in CI come from recorded responses instead
  (below).
- **Providers and failure handling:**
  - Bedrock comes first, through `anthropic.AnthropicBedrock` (InvokeModel).
  - There is no Anthropic API fallback for customer data (D-11, 23 Oct 2026): the API offers no EU processing or
    storage. The client path stays for dev only, where `ANTHROPIC_MODEL_<CLASS>` and `ANTHROPIC_API_KEY` exist;
    staging and production never set them.
  - Bedrock data retention is `none` in every Region the EU profile lists; it is set per Region through the API.
  - Each provider has a timeout, the SDK's bounded retries and a circuit breaker (5 consecutive failures open it for
    60 s, reported to Sentry).
  - When no provider answers, the call raises `ModelUnavailable` and callers withhold with `model_unavailable`.
- **Records:**
  - Each call writes one `app.model_calls` row with the configured model id, `<purpose>.<version>`, the input hash,
    tokens and latency. `cost_eur` stays null until Bedrock EU prices and a USD→EUR source are decided (issue #17).
  - Each call is also one Langfuse generation inside the job's trace.
- **Record and replay (`MODELS_MODE`):**
  - `live` (the default) calls providers.
  - `record` calls them and writes `worker/tests/cassettes/<purpose>/<input hash>.json`.
  - `replay` (the default when `NUTRIVO_ENV=ci`) reads those files and never touches the network; a missing file
    raises `CassetteMissing`.
  - The input hash covers the purpose, prompt version and text, model class, inputs and output schema, but not the
    model id, so cassettes recorded on dev replay anywhere.

## Evaluation before use
Each claim rule has an evaluation set per language in `worker/evals/claims/<lang>.jsonl`, labelled by a person
(permitted, prohibited, needs evidence). A claim rule may join a ruleset only when, for every language it covers,
agreement with the human labels reaches Cohen's κ ≥ 0.8 on at least 50 examples **and** nothing on the prohibited
set is judged permitted. A withheld judgement (abstained, below `min_confidence`, or a model error) is its own
category: it never agrees with a human label, it stays in κ and it counts toward the 50, so a model that abstains often
cannot pass on a small answered subset (#51). Until then the claims domain stays partial with a gap. Rerun on every
model or prompt change.

### The harness (T-501)
`scripts/env/run.sh dev -- uv run nutrivo evals claims --rule-key <key> --lang sv --lang da [--out report.json]`
(`nutrivo_worker.evals.claims`) judges every case of the named languages and prints a JSON report. It only reads:
it never changes a rule, a candidate or a ruleset.
- **Cases.** One JSONL file per language, format in `worker/evals/claims/README.md`. A human-labelled case names the
  person who labelled it and its source (a stored official source or accepted content), or the whole file is
  refused. `worker/evals/claims/synthetic/` holds the harness's own rule and cases (`--synthetic`): they test the
  harness, are not law, and can never meet the threshold (`synthetic_set`).
- **Rule.** The question, criteria, labelled examples and `min_confidence` are the params of the latest
  `claim_judgement` rule version that is not rejected (or `--rule-version N`). A case whose text is one of the rule's
  own examples is excluded (`example_overlap`). Examples are shown only in the case's language, or when they carry
  no language.
- **Judgement.** `claim_judgement.v1` gets the printed string and its `panel_language`, never a translation.
  - An abstention or a confidence below `min_confidence` is withheld as `model_abstained`.
  - A model error is withheld with its reason code (`model_unavailable`, `model_refused`, `model_output_invalid`).
  - Withheld is its own category in κ (confirmed on #51): it never agrees with a human label and counts toward the
    50 cases.
- **Threshold.** Per language: at least 50 cases, κ ≥ 0.8 and no prohibited case judged permitted. Otherwise the
  report gives the reasons: `too_few_cases`, `kappa_below_threshold`, `kappa_undefined` (chance agreement of 1),
  `prohibited_judged_permitted` or `synthetic_set`.
- **Exit codes.** 0 when every language meets the threshold, or a synthetic run is complete; 1 when not, or when the
  Langfuse record is incomplete; 2 when the set or the rule cannot be read.
- **Langfuse.** Each run is a dataset run (docs/17), named
  `<rule_key>@v<version> claim_judgement.<prompt> <UTC time>`.
  - There is one dataset per rule and language (`claims/<rule_key>/<lang>`) and one item per case, with an id
    derived from the case's id and text. Item metadata carries the case id and its source, never the labeller's
    name (docs/17).
  - Each case is a trace holding the model's generation.
  - Each case gets the scores `agreement` and `outcome`. The run gets `n`, `withheld`,
    `prohibited_judged_permitted`, `threshold_passed`, `kappa` and `agreement`.
- **Tests.** The harness's tests use a scripted fake model; CI never calls a model.

## Safety
Label and document text is data: it is passed in delimited blocks with an instruction to ignore instructions inside
it, outputs are schema-validated, and no tools are available during judgement. Only panel text is sent, never names
or emails. Provider: Bedrock on the EU geo profile with retention `none` (D-02, D-11).
